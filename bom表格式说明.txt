当前项目 BOM 标准格式说明

一、设计依据
1. 参考嘉立创 SMT BOM 文件标准：https://www.jlc.com/portal/server_guide_4070.html
2. 当前项目库存字段以 src/mainwindow.cpp 中 inventoryConfig() 定义为准。
3. 当前项目后续 BOM 导入将以“嘉立创兼容核心列 + 项目扩展列”的方式实现。

二、支持的文件格式
1. 推荐：.csv
2. 支持：.xls
3. 支持：.xlsx

三、推荐列顺序
说明：
1. 为兼容嘉立创 SMT BOM，前 8 列建议保持与嘉立创规则一致。
2. 为满足当前项目库存字段要求，在后面追加项目扩展列。
3. 后续导入建议按表头名识别，不强依赖列顺序；但模板文件请优先使用下列顺序。

推荐表头顺序：
1. Comment
2. Description
3. Designator
4. Footprint
5. LibRef
6. Pins
7. Quantity
8. 编号
9. Manufacturer Part
10. Manufacturer
11. Category
12. Unit
13. Location
14. Unique ID
15. Supplier
16. Batch No
17. Note

四、字段说明与内部映射
1. Comment
用途：器件型号、规格值、阻容值等，按嘉立创规则为重要字段。
内部映射：value
要求：建议必填。

2. Description
用途：器件名称或描述。
内部映射：name
要求：建议必填。

3. Designator
用途：位号，如 R1, R2, C3, U1。
内部映射：designator
要求：建议必填。
格式要求：
1) 位号之间只建议使用英文逗号或空格分隔。
2) 区间表达仅建议使用英文减号，例如 R1-R4。
3) 不支持中文位号。
4) 不建议使用特殊字符 @ # $ % ^ & { } [ ]。

4. Footprint
用途：封装，如 0402、0805、SOT-23。
内部映射：footprint
要求：建议必填。

5. LibRef
用途：原理图库器件名。
内部映射：device
要求：可选。

6. Pins
用途：焊盘数。
内部映射：pinCount
要求：可选，建议为整数。

7. Quantity
用途：数量。
内部映射：quantity
要求：必填，必须大于 0。

8. 编号
用途：嘉立创或采购侧使用的编号字段，嘉立创文档中属于重要字段。
内部映射：当前项目暂不直接入库存核心字段。
建议：
1) 如果是立创商城编号，可先写入 Note。
2) 后续如项目增加专用字段，可再单独映射。

9. Manufacturer Part
用途：厂家料号。
内部映射：manufacturerPart
要求：当前项目入库时必填。
说明：当前项目将 Manufacturer Part 作为库存唯一识别值，系统内不应出现重复的 Manufacturer Part。

10. Manufacturer
用途：厂家。
内部映射：manufacturer
要求：可选，用于分类、检索和展示。

11. Category
用途：物料分类，如 Resistor、Capacitor、IC。
内部映射：category
要求：可选，用于分类、检索和展示。

12. Unit
用途：计量单位。
内部映射：unit
要求：可选，用于展示。
默认值：个

13. Location
用途：库存位置。
内部映射：location
要求：可选，用于查询和库位管理扩展。
默认值：待上架

14. Unique ID
用途：项目内部唯一标识。
内部映射：uniqueId
要求：可选，仅作为扩展标识使用，不再作为主唯一识别值。

15. Supplier
用途：供应商。
内部映射：supplier
要求：可选。

16. Batch No
用途：批次号。
内部映射：batchNo
要求：可选。

17. Note
用途：项目内部备注。
内部映射：comment
要求：可选。
说明：嘉立创 SMT 规则会忽略备注，但当前项目内部仍保留该字段用于库存说明。

五、当前项目最小可导入字段集合
若要直接导入当前库存系统，建议至少提供以下字段：
1. Manufacturer Part
2. Quantity

以下字段建议同时提供，以提升匹配与追踪能力：
1. Description
2. Comment
3. Designator
4. Footprint
5. Manufacturer
6. Category
7. Unit
8. Location
9. Unique ID
10. Supplier
11. Batch No
12. Note

六、建议默认规则
当扩展列缺失时，后续导入逻辑建议按以下默认值处理：
1. Unit 缺失：默认填“个”
2. Location 缺失：默认填“待上架”
3. Date 缺失：默认使用导入当天日期
4. Category 缺失：默认填“未分类”，但正式入库前建议人工确认
5. Unique ID 缺失：允许为空，必要时再由后续扩展规则生成
6. Note 缺失：留空

七、嘉立创兼容性说明
1. 当前项目 BOM 标准优先兼容嘉立创 SMT BOM 的核心列：Comment、Description、Designator、Footprint、LibRef、Pins、Quantity、编号。
2. 当前项目比嘉立创 BOM 多出库存管理所需列，如 Manufacturer Part、Manufacturer、Category、Unit、Location、Unique ID。
3. 如果外部 BOM 仅满足嘉立创最小要求，而缺少库存字段，则应先进入“导入预览/补全”流程，不应直接写入库存。
4. 当前项目库存导入的硬性核心字段只有 Manufacturer Part 和 Quantity，其余字段均视为扩展信息。

八、后续导入实现建议
1. 先按表头识别嘉立创核心列。
2. 再识别项目扩展列。
3. 缺失字段使用默认值或进入人工补全。
4. 最终统一映射到当前项目库存字段。

十、当前 BOM 出入库最小实现规则
1. 当前项目 BOM 入库与 BOM 出库，已经支持只读取两列完成业务处理。
2. 必需列：Manufacturer Part、Quantity。
3. 允许识别的 Manufacturer Part 别名包括：Manufacturer Part、ManufacturerPart、Part Number、PartNumber、MPN、厂家料号、料号。
4. 允许识别的 Quantity 别名包括：Quantity、Qty、数量、用量。
5. 其他列即使存在，当前 BOM 出入库流程也不会作为硬性输入。
6. BOM 入库：按 Manufacturer Part 匹配已有库存，命中则累加入库数量，未命中则新建库存记录。
7. BOM 出库：按 Manufacturer Part 匹配已有库存，命中则扣减数量，未命中则报错。
8. Quantity 必须为大于 0 的整数。

九、推荐模板表头示例
